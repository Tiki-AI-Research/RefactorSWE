## Background
The X11 window manager's window frame currently owns three unrelated concerns at once: window geometry and lifecycle, decoration rendering (pixmaps, graphics contexts, theme application), and the pointer-interaction state machine (drag, resize edges, hover, double-click). Interaction state such as the mouse origin, move/resize flags, resize start sizes, hovered target, click counter, and the double-click cancel timer is stored implicitly next to decoration and geometry fields, so pointer events reach directly into rendering and geometry internals. This coupling makes pointer behavior hard to exercise without an X connection and forces unrelated changes through one oversized type. The work must separate the pointer-interaction state machine and decoration rendering into two collaborators, leaving the frame responsible only for window geometry and lifecycle, without changing any user-visible or externally observable behavior.

## Goal
- Move the pointer-interaction state machine (drag, resize edges, hover tracking, double-click detection, resize-cursor selection) out of the frame into a dedicated collaborator that owns its interaction state.
- Move decoration rendering (pixmaps, graphics contexts, theme application) into a separate collaborator, leaving the frame with window geometry, geometry queueing, and lifecycle only.
- Expose only a controlled geometry read/write surface and a theme-refresh entry point to the interaction collaborator instead of direct field access.
- Keep the frame's observable behavior and the X11 mouse-notification routing path intact, including argument forwarding and call order.
- Cover the pointer and geometry decision logic with pure unit tests that need no X connection: title-bar center selects move-only; the four edges and corners select resize flags; fixed-size or maximized windows disable resizing; a maximized window dragged outside the title bar by more than 84 times the canvas scale cancels maximization.

## Public contract to preserve
- The four window-client pointer notifications (drag, motion, press, release) MUST remain the entry points for pointer input and MUST keep their signatures: drag and motion take an x and y pixel coordinate as signed 16-bit integers; press and release additionally take the pointer button; none return a value.
- The press path MUST keep accepting only the primary button and MUST keep the same observable effects: raise and focus when unfocused, early return when fullscreen, ignored drag when a tappable child is hit, and raising the window at the end of processing.
- Geometry updates queued from interaction MUST keep their observable form: position and size as integer x/y and width/height plus a force flag, with interaction-driven moves and resizes queued without forcing.
- A theme refresh after hover changes MUST remain available to the interaction collaborator, preserving the existing refresh call semantics.
- Collaborator naming, internal structure, state placement, and how geometry access is exposed may be chosen freely, as long as the observable contract and the behavior below hold.

## Behavior that must stay unchanged
- Pointer press MUST classify the target exactly as before: primary button only; unfocused windows raise and focus and then return; fullscreen windows return; a tappable child marks the drag ignored and returns; otherwise the title bar's draggable center selects move-only, the title bar's left and right strips select top resize plus the matching left or right flag, and below the title bar the left and right edge strips select the matching left or right flag at any height, the bottom strip also selects bottom resize, and bottom corners combine bottom resize with the matching horizontal flag; fixed-size or maximized windows select no resize flags.
- Pointer drag MUST ignore the event when the window is fullscreen or the drag is ignored and MUST be a no-op for zero displacement; while maximized it MUST only unmaximize when the pointer is outside the title-bar vertical range and the absolute vertical movement exceeds ceil(84 times the canvas scale), restoring the horizontal position by the restore-width over width ratio and the vertical position to the pointer, and otherwise leaving the window untouched; otherwise it MUST translate on move-only and adjust width and height per active resize edge, clamping negative dimensions to zero, and queue geometry without forcing.
- Pointer motion MUST select the close cursor for close-cursor targets; MUST keep the hover transitions (mouse-in on first hover, mouse-out plus mouse-in when the target changes, mouse-moved on the same target, mouse-out when the pointer leaves) and MUST refresh the theme only when hover state changes; MUST look up the resize cursor from relative coordinates only when no object is hit and the window is not maximized, fullscreen, or fixed-size; and MUST finally set the cursor attribute on the frame window that receives these pointer notifications.
- Pointer release MUST clear the drag-ignore state for every release, MUST count a click only for a primary-button release whose frame-relative y is at most the title-bar height (including equality), without adding horizontal or lower-y bounds, and MUST keep double-click timing semantics: a second click within the existing deadline on a double-tappable target triggers double-tap, a single click triggers tap, and cancelling a pending timer behaves as before.
- The X11 mouse-notification path MUST forward each event to the interaction handling with identical arguments and unchanged call order, and MUST NOT introduce additional, dropped, or reordered notifications.

## constraints
1. Behavior drift is prohibited beyond the responsibility split: keep all existing geometry math, thresholds, cursor choices, hover and double-click semantics, and event ordering exactly as they are today.
2. Do not reduce capability: no entry point, hover or double-click support, theme-refresh path, or observable side effect may be removed, renamed, or narrowed.
3. Do not add third-party dependencies or expand existing dependency usage beyond what the module already imports.
4. Do not change exported API or unrelated packages; keep changes confined to the X11 window-management package.
5. Modification scope: limit changes to the production code needed for the split and delegation, package-internal unit tests covering the geometry and interaction branches that require no X connection, and minimal supporting adjustments; do not perform unrelated refactors, renames, or formatting churn.
