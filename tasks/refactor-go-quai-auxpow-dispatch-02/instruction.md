# Consolidate auxiliary proof-of-work dispatch

Header construction, JSON decoding, protobuf decoding, and transaction hashing repeat the same four-way proof-of-work identifier mapping. Replace that branching with one dispatch decision per responsibility, letting existing chain header types own defaults, byte layouts, and transaction hashing. Chain adjustments should no longer require edits to the shared dispatch sites. Use the existing header abstraction as the only seam; introduce no parallel hierarchy or new public types/API. Private dispatch mechanisms, helpers, and placement are yours to choose.

Keep all exported symbols and signatures: `NewBlockHeader` retains identifier/version/previous hash/merkle root/time/bits/nonce/height ordering and return shape; per-chain constructors/wrappers remain; the shared abstraction retains serialization, deserialization, block/PoW hash, copy, and field accessors. Identifier numeric values, string forms, and unknown fallback remain unchanged. `AuxPowTxHash` retains its identifier/raw-transaction inputs and 32-byte result.

Preserve JSON fields `powId`, `header`, `auxpow2`, `signature`, `merkleBranch`, and `transaction`; protobuf optional fields, numbers, and layout remain unchanged, including signature time. Supported identifiers must retain byte-identical round trips and chain-specific header layouts, including KAWPOW height, nonce64, and mix hash. Block, PoW, seal, and transaction hashes remain identical; KAWPOW's PoW input still excludes nonce64/mix hash. `AuxPowTxHash` retains current double-SHA256 chain outputs for KAWPOW, SHA_BTC, SHA_BCH, and Scrypt, and returns zero for other identifiers.

Unknown identifiers keep their path-specific outcomes: construction returns nil, protobuf decoding errors with `unsupported powId for AuxPow header`, and JSON decoding succeeds and populates other fields without assigning or clearing the header: a zero-valued receiver stays unset, while a reused receiver retains its previous header. Propagate header deserialization failures without panicking on malformed/truncated bytes. Record the identifier before decoding the header; a header error leaves it set and remaining payload fields untouched. Nil protobuf input returns nil without mutating the receiver; absent inner headers retain zero-valued hashes. Preserve validation/error precedence for multiply invalid payloads.

Completion requires removal of duplicate identifier dispatch while retaining the supported chain set, serialized bytes, hashes, and errors, with accompanying tests. Add no dependencies; reuse existing chain libraries. Restrict production edits to dispatch and necessary per-chain helpers; do not edit generated protobuf code, unrelated packages, or perform unrelated refactors/formatting.

Work in a new branch from `main` and commit the completed changes.
